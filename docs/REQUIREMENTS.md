# missmatch 要件定義

最終更新: 2026-10-17（噛み合い判定に雰囲気・規模を渡す、失敗したバッチの再試行、言葉の読み取りのキャッシュ、KV の一括読み、雰囲気の欠けを判定の前に待たない）

## 1. コンセプト

**「Misskey サーバー選びを、マッチングアプリの体験に変える」**

日本語の Misskey サーバーは 600 以上あり、そのうち新規登録を受け付けているのは約 100 件。
どこに入るかで体験は大きく変わるのに、比較材料は「サーバー名と一行説明」しかなく、
初心者は結局いちばん大きいサーバーに流れる。

missmatch は、ユーザーが書いた **言葉** と、各サーバーの **実用面の属性**（登録要件、機能、ドライブ容量、広告、更新状況など）と
**雰囲気**（説明文・ルール・実際の投稿から AI が読み取ったもの）を突き合わせ、合う順にカードで提示する。
ユーザーはスワイプで直感的に選び、気に入ったサーバーを一覧に残して見に行く。

### 体験の骨格

- **言葉で探す**: ChatGPT のように、最初は入力欄だけ。「病み垢を置ける、静かで干渉が少ない場所」のように書いて送る
- **言葉を重ねて絞る**: デッキを見ながら「もっと絞る」で言葉を足すと、言葉の並び全体を読み直して並べ替える
- **聞き返しは選択肢だけ**: 言葉から読み取れなかった軸（規模・流速・空気感・関わり方・ルール）だけを、生成文ではなく選択肢のチップで 1 問ずつ聞く
- **好みはスワイプから学ぶ**: 質問で好みを聞き出さない。いいね / よくないねからサーバーの特徴ベクトルに寄せて学び、次の束を並べ替える
- **検索はセッション**: 言葉ごとに検索として残し、サイドバーから戻れる。いいね・よくないね・読み取り結果・学んだ好みは検索ごとに分ける（別の目的で外したサーバーが次の目的で消えたままにならない）

質問文を実行時に生成することはしない。生成しても、その質問に対する候補サーバー分の答えが無ければ絞れないからである。
代わりに Clef には 2 つの判定を任せる。(1) 各サーバーの雰囲気（事前計算）、(2) ユーザーの言葉と各サーバーが噛み合うか（言葉ごと、候補を直接判定）。
後者により、設定項目に無い切り口（例: 病み垢の居場所）でもサーバーの説明文や投稿に表れていれば拾える。
属性表は事前計算し、絞り込みと採点はブラウザ内で完結させる。

### 姉妹プロジェクトとの関係

| プロジェクト | 立場 | 役割 |
|---|---|---|
| misspace | 見せる | 連合グラフを可視化し、ユーザー自身が判断する |
| **missmatch** | 勧める | 言葉を聞いてこちらから候補を出す |

missmatch の「いいね」からは misspace の連合グラフ（`?from=<host>`）へ遷移でき、
「勧められたサーバーがどの界隈と繋がっているか」を続けて確認できる。

### 設計原則

0. **実際に差がある項目だけ使う**: サーバー間で差がつかない項目（例: 投稿の最大文字数は 95 件中 90 件が 3,000 字）は条件にしない。条件を足すときは実データで分布を確かめる
1. **最終判断はユーザー**: 相性は「見に行く順番」の提案であって、サーバーの優劣ではない。登録はさせない
2. **理由を見せる**: カードに一致理由を、デスクトップの右パネルに Clef の判定値を出す。判定できなかったものは「未判定」と正直に出す
3. **実データで校正する**: 選択肢や閾値は joinmisskey の実分布に合わせる。勘で決めない
4. **初期状態はできるだけ多く通す**: 何も選んでいないのに候補を削る・強く減点する初期値は置かない
5. **サーバーに礼儀正しく**: 各サーバーへの API 呼び出しは 1 週間に 1 回程度（KV キャッシュ）。User-Agent を名乗り、タイムアウトを守り、LTL を公開していないサーバーには触らない
6. **ユーザー情報を持たない**: 設定と検索はブラウザにだけ保存する。ログインもクッキーもなし

## 2. 対象ユーザー

- **P1: Misskey を始めたい人**。Fediverse 用語に不慣れ。misskey.io 以外の選択肢を知らない。
- **P2: サブアカウントの居場所を探している経験者**。「創作垢を置ける落ち着いたサーバー」など目的が具体的で、目的ごとに探し直す。
- 共通: 日本語話者。スマートフォンでは片手操作、デスクトップでは縦スクロールなしで 1 画面に収まること。

## 3. スコープ

### 対象サーバー

- joinmisskey (`instanceapp.misskey.page/instances.json`) に登録され、`isAlive` かつ `langs` に `ja` を含む
- 既定では **新規登録を受け付けている**サーバー（`nodeinfo.openRegistrations`、無ければ `meta.disableRegistration` から判定）と、
  **生きている招待制**（`dru15` ≥ 1、1 日 1 人以上が読んでいる）のサーバー。招待制は既存ユーザーの紹介で入れるので、初めから見せる
- 「登録のしかた」で停止中を含めると、登録停止中でも生きているサーバーも候補になる
- 2026-10 時点の実数: 日本語で生きているもの 652 件 → 登録受付中 **95 件**、招待制まで **185 件**、停止中を含めると約 **580 件**

#### 登録状態の判定

公開情報に「招待制」の直接のフラグは無い。次の順で判定する。

| 状態 | 判定 |
|---|---|
| open | 登録受付中で承認不要 |
| approval | 登録受付中で `approvalRequiredForSignup` |
| invite | 停止中で、`policies.canInvite`（一般ユーザーが招待コードを発行できる）か、説明文・ルールに「招待」「invite」 |
| closed | 停止中でそれ以外（misskey.io のような一時停止を含む） |

### やらないこと

- アカウント作成・ログイン・サーバーへの投稿
- サーバーの「品質」や「安全性」のランキング（モデレーション判定は misscore の領域）
- 多言語対応（日本語サーバーの雰囲気判定に特化する）
- ユーザーの検索や行動のサーバー側への保存

## 4. 機能要件

### F1. 言葉で探す

#### F1-a. 画面の流れ

- アプリは `/` の 1 ページ（`/pick` は `/` への 308 リダイレクトだけ残す）。サイドバー（モバイルはドロワー）に、さがす / いいね / よくないね / あなた、さがした言葉の一覧、「新しくさがす」
- 初回だけ **年齢（3 択）と R-18（3 択）** を聞く。サイドバー付きの画面の中で出し、1 画面に収める
- 「さがす」で今の検索に言葉が無いときは **ランディング**（ロゴ・入力欄・例文 4 つ・惑星の背景）を出す。送ると、その検索の言葉になって読み取りが始まる。同じ言葉の検索が既にあればそれを開く
- 言葉があるときは、デッキと右パネル（デスクトップ）と「もっと絞る」入力欄を出す
- 「新しくさがす」とロゴは、言葉の無い検索（ランディング）に戻る。言葉の無い検索は一覧に出さない

#### F1-b. 検索（セッション）

`Search` を言葉ごとに持ち、localStorage の `SavedProfile.searches` に保存する。

| フィールド | 内容 |
|---|---|
| query / turns | 最初の言葉と、そのあと足した言葉（「もっと絞る」）。足した言葉はチップで外せる |
| title | 付けた名前（「…」メニューで変更。空なら query） |
| intent / choices | Clef の読み取り結果と、聞き返しへの答え |
| affinity / affinityFor | 各サーバーとの噛み合い確率と、それを読み取ったときの言葉の並び（並びが変わると読み直す） |
| unsure | 読み取れず、選択肢で聞く軸 |
| taste / swipes | この検索のスワイプから学んだ好み |
| liked / passed | いいね・よくないねした host |

一覧はサイドバーに、最後に使った日で「今日 / 昨日 / 過去 7 日 / それ以前」にまとめる。1 行は題名だけで、操作はホバーで出る「…」（名前を変更 / 消す）に集約する。

#### F1-c. 言葉の読み取り

言葉の並び（最初の言葉 + 足した言葉、古い順。食い違えば後を優先）を `POST /api/intent` に送り、Clef で 2 種類の判定をする。

1. **設定の読み取り**: 話題（noul × 14）、空気感・関わり方・ルール・規模・流速（choice: 左 / 右 / 言及なし）、
   メアド不要・広告なし・GTL・本家（noul）。確率 0.6（noul は 0.7）以上のものだけを使う。年齢と R-18 は読み取らない。
   **規模・流速は読み取りからはハードフィルターにしない**（噛み合い判定が規模・流速を見て加減する）。評価セットで、
   「のんびり雑談」の pace=quiet で大手 3 件が全部消え、「盛り上がりたい」の pace=busy でアニメ実況の小さな鯖が消えていた。
   聞き返しの選択肢でユーザーが選んだときだけハードフィルターになる
2. **噛み合い確率（affinity）**: 候補それぞれについて「ユーザーが望む使い方・話題・居心地に合う場所か」を `noul` で問う。
   16 件ずつのバッチを並列に投げる（実測: 8 件 recall@5 81% / p50 2.1 秒、16 件 86% / 2.2 秒、32 件 81% / 2.6 秒。
   同じ state に並ぶ数が多いほど物差しがそろって精度が上がるが、32 件では落ちて遅くなる）。各サーバーについて渡すのは、
   名前・説明文 300 字・ルール 200 字・**規模と流速**（「小規模（毎日 8 人が読む）」「のんびり（〜100投稿/日）」と登録者数）・
   **雰囲気の判定値を言葉にしたもの**（空気感とルールは段階の文、初心者歓迎・身内ノリ・成人向けは %。未判定なら付けない）・
   **話題の確率**（0.5 以上を「ゲーム 90%」の形で）・**LTL の有無**（無い鯖は流速が速くても本人のホームは静か）。
   「静か」「身内」「初心者でも」のような希望は説明文だけでは読めないことが多いので、事前計算した判定を見せる。
   **最近の投稿の抜粋は渡さない**: 瞬間の LTL は bot・ニュース・告知が多く、誰でもする食べ物や仕事の話がどの鯖にもあるので、
   説明文で決まるテーマ性を薄めるだけだった（2026-10-17、長い投稿 5 件を渡して recall@5 82 → 74%。うち大半は state が
   大きくなった 1 バッチが Clef の決定を返せず 8 件が 0.5 になったせいだが、抜粋の中身も材料として悪かった）。
   失敗したバッチは半分に割って投げ直し、それでも駄目なら残りの結果だけを使う（以前は 1 本の失敗で全サーバーが 0.5 になっていた。
   同じ入力をそのまま投げ直しても、Clef が決定を返せない入力なら同じ結果になる）。
   **再ランキングは採らない**: 第 1 段の上位 16 件を 1 つの state に並べ「他と比べてどれだけ合うか」を 5 段階で問い半々に混ぜる案を
   A/B で測ったが、recall@5 84 vs 83%、MRR 90 vs 89% と誤差の範囲で、応答が 1.6 → 2.8 秒に伸びた（2026-10-17、32 言葉）。
   雰囲気の欠けは判定の前に待たず、`waitUntil` で応答後に埋める（以前は欠け 40 件の LTL 取得と Clef を待ってから判定を始めていた）。
   同じ言葉の並び（と scope）の結果は KV に 7 日置き、2 回目からは Clef を呼ばずに返す（全バッチがそろったときだけ置く）。送った言葉は Workers AI の無料枠（1 日 10,000 Neurons）に関係なく必ず判定する。枠を守るのは裏側の仕事だけで、先読みは 5,000 を超えたら 503 で断り、例文の温めと雰囲気の欠け埋めは 9,000 で止めて翌日に回す（`src/lib/server/budget.ts`）

読み取り結果は **その検索にだけ** 持たせ、全体の設定には書き込まない。並べるときに `effectivePrefs` で
「全体の設定の空いている所を読み取りで埋め、聞き返しの答えで上書きしたもの」を作る。
（以前は全体の設定に書き込んでいたため、話題が積み上がり、別の検索にも空気感やメアド不要が残って精度を落としていた）

読み取り中は、カードの上にぼかしとスピナー（misskey-hub と同じ形）を重ねて古い並びを隠し、判定パネルと操作ボタンを触れなくする。

実測（2026-10-15、Clef 実機、旧版の 12 件バッチ）: 「病み垢として運用したい。弱音や愚痴を吐いても浮かない、静かな場所がいい」→ 噛み合い 1 位 yami.ski 0.92。

`POST /api/intent` は `fresh: true` でキャッシュを読まずに判定し直す（評価スクリプト用）。

#### F1-d. 選択肢での聞き返し

Clef の choice の回答が「言及なし」か低確率だった軸を `unsure` に覚え、入力欄の上の行に 1 問ずつチップで出す
（「規模は？ 小さなコミュニティ / 人の多い大手 / こだわらない」）。答えるとその検索の `choices` に入り、「こだわらない」で消える。
全体の設定で既に決めた軸は聞かない。1 問 1 行に固定し、入りきらない選択肢は横にスクロールする。

### F2. 「あなた」（全体の設定、1 画面）

すべて 1 タップで決まり、該当件数を常時表示する。デスクトップでは 3 列（基本 + 規模と流速 / 話したいこと + 空気感 / 学んだ好み + 絶対条件）に振り分け、縦スクロールなしで収める。

| 区分 | 項目 | 操作 | 効き方 |
|---|---|---|---|
| 基本 | 年齢 | 18 歳以上 / 12〜17 歳 / 12 歳未満 | ハードフィルター（F3、下限年齢で判定） |
| 基本 | 毎日いる人 | 気にしない / 10 人以上 / 100 人以上 | ハードフィルター（`dru15`）。95 件中 10 人未満が 38 件、100 人以上が 18 件 |
| 基本 | R-18 の投稿 | 見たくない / 気にしない / 歓迎 | 「見たくない」で重み 4、「歓迎」で重み 2 の加点。初期値は「気にしない」 |
| 話したいこと | 14 区分（特定テーマを除く） | チップ、複数可 | 選んだ話題のうち最大の `vibe.genre` を重み 3 で加点 |
| 空気感 | 空気（ドライ ↔ ほのぼの）/ 関わり方（濃い身内 ↔ 初心者歓迎）/ ルール（ゆるめ ↔ しっかり） | 3 段セグメント | 重み 2 / 2 / 1.5 で加点（F5 の相対値で採点） |
| 規模と流速 | 個人（毎日 〜2 人）/ 小（3〜29）/ 中（30〜299）/ 大（300〜）、のんびり / ほどほど / にぎやか | チップ、複数可、空 = 指定なし | ハードフィルター。規模は **1 日の読者数（`dru15`）** で決める。登録者数は離れた人を含んで膨らみ、登録 1,142 人で毎日 8 人の鯖が「大手」になっていた。95 件の分布は 20 / 36 / 26 / 13（登録者数だと「個人」は 1 件だけ） |
| 絶対条件 | 登録のしかた（受付中・承認制・招待制・停止中、既定は前 3 つ） | チップ | ハードフィルター。招待制を含めると約 185 件、停止中を含めると全件（約 580 件）を取りに行く |
| 絶対条件 | 登録・タイムライン: メアド不要 / 広告なし / ローカル TL / グローバル TL | チップ | ハードフィルター |
| 絶対条件 | 機能: ノート検索 / 翻訳 / チャット / 動画アップロード / ドライブ 10GB 以上 | チップ | ハードフィルター |
| 絶対条件 | 運営: 本家のみ / 最新版（1 ヶ月以内）/ 利用規約あり / プライバシーポリシーあり | チップ | ハードフィルター。該当が 5 件未満で警告 |
| 学んだ好み | 今の検索で学んだ傾向 | チップ（個別に忘れる）、リセット | F4 |

「初期値に戻す」で年齢以外をすべて初期値に戻せる。

機能・運営の条件は joinmisskey の `meta` と一般ユーザーのロールのポリシーから読む。書いていなければ「ない」とみなす。
登録受付中 95 件での該当数（2026-10）: ローカル TL 86、ノート検索 62、翻訳 47（サーバーで有効かつ一般ユーザーに許可）、
チャット 74、動画 78、ドライブ 10GB 以上 15、利用規約 77、プライバシーポリシー 42。
長文（3,000 字超、5 件）・多言語（5 件）・予約投稿・連合あり（ほぼ全件）は差が出ないので入れていない。

### F3. 年齢制限の判定

説明文とサーバールールから **登録できる下限年齢**（`minAge`、数値）を読む。内容の成人向け度（nsfw）とは別の概念であり、混同しない。

- 文ごとに読み、投稿内容を表す語（自撮り・顔・写真・投稿・ミュート・描写・個人情報・コンテンツ・R18・NSFW など）を含む文は対象外
- 「N歳以上」は、限定・のみ・であること・である必要・ご利用・登録できる・推奨 などの制限の語と同じ文にあるとき
- 「N歳未満」は、禁止・できません・不可・お断り・ご遠慮・いただけません・非推奨 などの語と同じ文にあるとき。禁止事項の列挙（「18歳未満の者による利用。」）も拾う
- 未成年の登録禁止・成人に満たない方は不可・成人限定は 18、「小中学生向けではありません」は 15、「中学生以上」は 12
- 複数あれば一番高い下限を採る。書いていなければ `null`（制限なし扱い）

| 年齢 | 出さないサーバー |
|---|---|
| 18 歳以上 | なし |
| 12〜17 歳 | 下限が 18 歳以上 |
| 12 歳未満 | 下限のあるサーバーすべて（12 歳以上が必要） |

日本語 652 件での結果（2026-10-16）: 12 歳 2 / 13 歳 13 / 15 歳 4 / 16 歳 3 / 18 歳 22 / 20 歳 2、計 46 件。
旧版は「18歳以上限定」「13歳未満の登録は禁止」など決まった言い回しだけを 18+ / 13+ の 2 段で拾っていたため 20 件しか判定できず、
「12歳未満の新規登録は禁止」「15歳未満の登録…禁止」「18歳未満の方はご利用いただけません」「20歳以上のユーザが登録できます」などを
制限なしとして、どの年齢にも出していた。さらに前の版（`成人|nsfw|r-?18` の正規表現）は内容ルールまで 18+ と誤判定していた。

### F4. スワイプからの学習

- サーバーごとに特徴ベクトル（0..1）を持つ: 話題 14 軸、空気、ルール、関わり方、R-18、規模、流速、ドライブ容量、本家、GTL、メアド不要、広告なし、更新の新しさ。判定できない特徴は含めない。空気・ルール・関わり方は F5 の相対値を使う
- 好み `taste` は **検索ごと** に特徴ごと -1..1。いいねで `+0.3 × (f − 0.5) × 2`、よくないねで `−0.15 × …`（弱い信号）
- 採点の軸として `tasteFit` を、重み `min(3, スワイプ数 / 8 × 3)` で加える。最初は効かず、8 スワイプで最大
- 絶対条件の領分（メアド・広告・GTL・更新）は学ばない。話題とドライブ容量は「好き」の方向だけ学ぶ
- デッキは 10 枚ずつ。束を見終わると、学習した好みで次の 10 枚を並べ直す（見ている最中に順番は変えない）
- 戻す は直前の学習を同じ量だけ戻す。よくないねしたサーバーはその検索では二度と出さず、「よくないね」タブから戻せる

### F5. 雰囲気プロファイル（VibeProfile）

各サーバーについて以下を Cloudflare Workers AI の決定モデル **Clef**（`@cf/cloudflare/clef`）に 1 リクエストで問う。
Clef は文章を生成せず、型付きの質問に校正済みの確率で答える。

| 軸 | 型 | 内容 |
|---|---|---|
| genre.*（15 区分、下表） | noul（各 0..1） | その話題が **目立つか**。独立に問うので「創作もアニメも多い」サーバーを表現できる |
| tone | score 4 段階 → 0..1 | 殺伐 → ドライ → 穏やか → ほのぼの |
| strictness | score 3 段階 → 0..1 | ルールの厳しさ |
| newcomerFriendly | noul | 初心者が会話に入りやすいか |
| nsfw | noul | 成人向け投稿が目立つか |
| closedCommunity | noul | 身内ノリが強いか |

**state に渡す情報**: サーバー名、説明文、ルール、ユーザー数、投稿数/日、最近の投稿サンプル（最大 50 件）。
投稿は雰囲気の判定にだけ使い、保存しない。

**ジャンルの区分**は、登録可能な日本語サーバーの名前・説明文・ルールに実在するコンセプトを集計して決めた（2026-10-15）。

| 区分 | 実在する例 |
|---|---|
| 雑談 | すしすきー、Misskey.gg、まっちゃすきー ほか多数 |
| 日記・ひとりごと | わふふすきー、metreee、たけすきー、だらだら倶楽部 |
| イラスト・漫画を描く | お絵かきすきー、misskey.art、misskey.design、Pika.moe |
| 小説・文章 | misskey.design、イノカシラシクィイ |
| 音楽・歌 | ぼすきー（合成音声）、nicomedkey、にしかわたかのりすきー |
| ものづくり・制作 | くらふたーず、roboticskey、DAZ（3DCG）、misskey.doujin.games |
| 技術・IT | みすてむず、競プロ鯖、労働者たちの Misskey |
| ゲーム（TRPG・ボドゲ含む） | 卓すきー、いかすきー、パズルゲームすきー |
| アニメ・漫画 | 星海天測団、Misskirara、misskey.stream |
| 推し活・ファン | LIVE THE@TER NET、ゆにくすきー、ESkey、封神台、u-stella |
| VRChat・メタバース | にりらみすきー部、ぶいちゃ、Resonite.love、バーチャルケモミミ |
| 食べ物・お酒 | ぽてとすきー、うま味、kusso-yotta |
| 動物・ペット | いぬすきー、kusso-yotta |
| 愚痴・弱音 | やみすきー、みつきー、かせいすきー |
| 特定テーマ（話題としては選べない） | 地域・職業などの限定サーバーの検出用。多くのサーバーで高めに出るので、タグは 0.8 以上のときだけ付ける |

**判定値の偏り**（95 件、2026-10-16）: tone は平均 0.66・標準偏差 0.12 でほぼ全員が「やや穏やか」に固まる。
そのため採点では、空気感・ルール・初心者歓迎・身内ノリを **候補の中での順位（0..1）** に直して使う（`withRelativeVibes`）。
右パネルの表示は元の判定値のまま。また投稿サンプルが 10 件未満のサーバーが 22 件あるので、
投稿から読む軸（空気感・関わり方）は `0.3 + 0.7 × サンプル数 / 30`（上限 1）の確信度で中立に寄せる。
話題は説明文からも読めるので寄せない（やみすきーは LTL 非公開で投稿 0 件だが「病んでいい場所」から愚痴・弱音 0.95。寄せると 0.64 になっていた）。

### F6. 投稿サンプリング

- 未認証で `POST /api/notes/local-timeline` を叩き、renote と添付のみの投稿を除く
- `meta.policies.ltlAvailable` が false のサーバーには **リクエストしない**。説明文とルールだけで判定する
- 100 件取得して **50 件** を使う。URL・メンションを除き、1 件 200 文字まで
- **1 ユーザーあたり最大 5 件**。瞬間的な LTL は 1 人の連投で埋まりがちで、そのままでは個人の雰囲気を測ってしまう
- CW 付き投稿は CW 本文を先頭に付けて含める（成人向け度の手がかりになる）
- タイムアウト 8 秒、失敗は空配列（判定は続行）

### F7. 採点と提示順

1. ハードフィルター: 日本語・登録のしかた・年齢・毎日いる人・規模・流速・絶対条件
2. 好みの適合度 = 軸ごとの適合度（0..1）× 重みの加重平均。軸が無ければ 0.5
3. **言葉があるとき** は `相性 = 0.75 × 噛み合い + 0.25 × 好みの適合度`。言葉との噛み合いが主で、設定と学習した好みは従
4. 適合度 0.6 以上の軸の理由をカードに出す（「創作の話題が多い」「書いてくれた希望と噛み合う」「いいねした鯖と似ている」）
5. 雰囲気未判定のサーバーは雰囲気系の軸を 0.5 とする
5'. 関わり方が「初心者でも気軽に入れる」（設定か読み取り）のときだけ、毎日読む人の少なさで最大 10% 下げる（対数、300 人で 0%）。
   「初めての Misskey」で毎日 4〜8 人の鯖が上位を占めていたため。判定基準に「人がいること」を足す案は、言葉に関係なく小さな鯖を全部下げて recall@5 88 → 82% になったので採らない
6. 同点は `dru15` の多い順。その検索でスワイプ済みのものを除いて上位 10 件をデッキにする

| 軸 | 重み |
|---|---|
| R-18 = 見たくない | 4 |
| 話題、学習した好み（最大） | 3 |
| 空気、関わり方、R-18 = 歓迎 | 2 |
| ルール | 1.5 |

### F8. 画面

UI 言語は misskey-hub（Misskey 公式サイト）に倣い、骨組みは yamix、部品の作法は misspace に倣う。

- **骨組み**: デスクトップ（900px 以上）は固定幅 250px のサイドバー + 本文。モバイルは下タブバー（左端がメニュー）で、同じサイドバーをドロワーで出す
- **デスクトップは縦スクロールなし**: さがす・あなた・オンボーディングとも 1440×760 で 1 画面に収める。左のカード（640px）は縮めず、収まらない画面では右パネルが先に縮む
- **さがす**: 左にカードの束と操作（戻す / よくないね / いいね）。右に判定パネル（Clef の判定: 言葉との噛み合い、空気感・ルールは位置マーカー、初心者歓迎・身内ノリ・成人向け・話題上位 3 つは塗りのバー、判定に使った投稿数。事実: アクティブ・ドライブ・メアド・広告・GTL・本体）。右パネルは左のカードと情報を重複させない。その下に「もっと絞る」入力欄が残りの高さを埋める。モバイルは詳細をボトムシートで出し、入力欄は下タブバーの上に貼り付く
- **カード**: 全面にバナー（無ければテーマ色のグラデーション）、名前・host・人数・投稿数（K/M 表記）、一致理由とタグのチップ、説明文 2 行。右上に相性（黄緑 #9ad11b に黒文字のピル）
- **いいね / よくないね**: 2 列のタイルグリッド。いいねから本体 / misspace の連合へ。空のときは枠を付けず、アイコンと一文だけ
- **ランディング**: 💘 のロゴ、入力欄（Enter で送る / Shift+Enter で改行）、例文チップ、惑星と星の絵文字が漂う背景（中央は抜く、reduced-motion では止める）
- **見た目**: Nunito + 丸ゴシック、太さは 400/700 の 2 段。主ボタンは #86b300 → #4ab300 のグラデーションと緑の影。単一選択はピル型トラックのセグメント、複数選択はチップ（選択中はチェック付き）。アイコンはインライン SVG。ロゴとファビコンは Microsoft Fluent Emoji（MIT）の 💘
- **マッチ演出**: 相性 70% 以上にいいねで全面オーバーレイ
- **描画の軽さ**: 属性表は `$state.raw` で深い reactivity を付けない。保存は 250ms デバウンス。カードは `contain: content` と `translate3d`。画像は joinmisskey が軽量化して配る webp を使い、各サーバー本体には取りに行かない

### F9. 事前計算（warm）

- `POST /api/warm?limit=&offset=` を Bearer トークン付きで手で叩く。既定は推薦され得るサーバー（日本語・登録受付中）、`scope=all` で招待制・停止中も
- 活発な順に処理する
- `mode=intents` はトップページの例文 16 個のうち、キャッシュ（7 日）が切れた分だけ読み取る。普段は Cloudflare の Cron Triggers（`wrangler.toml` の `crons`、1 日 1 回）が `src/worker.ts` の `scheduled` から同じ処理を回すので、例文は常に即答になる。枠を使い切ったら残りは翌日に回す

## 5. 非機能要件

| 項目 | 要件 |
|---|---|
| レイテンシ | 属性表 API も言葉の読み取りも Clef の雰囲気判定を待たない（キャッシュ済み分で進め、欠けは `waitUntil` で応答後に計算）。言葉の読み取りは 1 + ⌈候補 / 16⌉ リクエストを並列（既定の招待制までで約 13 本）、同じ言葉は KV のキャッシュから即返す。実測は `pnpm eval` で追う（2026-10-17、招待制まで 185 件: p50 2.2 秒、p90 2.8 秒。受付中のみ 95 件: p50 1.3 秒） |
| コスト | Clef 入力 $0.24/M トークン。雰囲気: 1 サーバー約 3K トークン → 95 件のフル更新で約 $0.07。言葉の読み取りは雰囲気・規模・話題の確率を足したぶん旧版（約 30K トークン、約 $0.01）より増える（評価 32 言葉で $0.5 前後）。招待制・停止中を含めると候補が約 6 倍になり、読み取りも比例して増える |
| キャッシュ | VibeProfile `vibe:<host>`: KV 7 日。サーバー一覧 `servers:v7`: 1 時間。組み立て済みの属性表 `profiles:v4:<scope>`: 欠けが無いときだけ 5 分。言葉の読み取り `intent:v5:<scope>:<言葉の SHA-256>`: 7 日（雰囲気は 7 日おきにしか変わらない。判定に渡す state や基準を変えたら上げる）。Clef の使用量 `ai:neurons:<UTC 日付>`: 2 日。形を変えたらキーを上げる（VibeProfile は `VIBE_VERSION`） |
| 外部負荷 | 各サーバーへの LTL 取得は 7 日に 1 回。並列 8。`User-Agent: missmatch/1.0` |
| Workers 制限 | 1 リクエストの外部操作は 1,000 回まで（KV の読み書きも数える）。属性表の組み立てでは `vibe:` を 100 鍵ずつの一括読み（1 操作）でまとめる。候補 40 件 × (LTL + AI + KV) は有料プラン前提 |
| プライバシー | サーバー探し: 設定・検索・いいねは `localStorage` のみ。言葉は読み取りのために Clef へ送るが保存しない。投稿は雰囲気の判定にだけ使い、保存もブラウザへの送信もしない。アクセス解析なし。マッチング（[PEOPLE.md](PEOPLE.md) §6）は別: 参加者本人の公開ノートを本人のトークンで読み、推定した数値・参加の記録・本人のフォロー一覧だけを保存する |
| 保存形式 | `missmatch:profile:v2`。`prefsVersion` が 2 未満の保存値は、読み取り結果が混ざっていた頃のものとして絞り込みと加点を一度だけ初期値に戻す（年齢・R-18・登録のしかたは残す）。3 未満で登録のしかたが当時の既定（受付中・承認制）のままなら、招待制を含む今の既定に移す。旧形式の adult・全体の学んだ好み・1 本だけのいいねは読み替える |
| アクセシビリティ | キーボードで操作できる（← → で判定、↑/Space で詳細、Backspace で戻す、Enter で送る）。ダークモード対応。装飾の背景は支援技術から隠し、reduced-motion では動かさない |

## 6. アーキテクチャ

```
joinmisskey instances.json ──→ normalizeInstance ──→ ServerInfo[]（KV 1h）
                                                       │ isJoinable / isListed
GET /api/servers ──→ KV の VibeProfile を一括読み（100 鍵/操作）──→ ServerProfile[] ──→ ブラウザ
                     └─ 欠け（活発な順に 40 件）は waitUntil で応答後に LTL 50 件 → Clef → KV 7d

言葉の並び ──→ POST /api/intent ──→ KV `intent:` にあれば即返す ──→ 無ければ Clef ×(1 + ⌈候補/16⌉) 並列（失敗分は割って再試行）──→ { 読み取り, affinity } ──→ KV 7d・その検索に保存
                                                                                          │
localStorage ⇄ SavedProfile{prefsVersion, prefs, searches[], current}                      │
                    effectivePrefs(prefs, search) ──→ withRelativeVibes ──→ buildDeck（ブラウザ内）──→ 10 枚 ──→ スワイプ ──→ learn（検索ごと）
```

- `/api/servers` と `/api/intent` は `scope=open`（約 95 件）、`scope=invite`（既定、生きている招待制まで約 185 件）、`scope=all`（停止中を含む約 580 件）を持つ。設定が要るぶんだけ取りに行く
- Clef が判定を返せないサーバー（例: `3043: The model did not produce a valid decision response`）は、投稿サンプル無しで再挑戦し、それでも駄目なら失敗マーカーを 1 日置く
- SvelteKit + adapter-cloudflare。設定（`prefs.ts`）、検索（`search.ts`）、特徴ベクトル（`features.ts`）、学習と採点（`match.ts`）、
  言葉の変換（`intent.ts`）、保存形式（`profile.ts`）、雰囲気（`vibe.ts`）は純粋関数で、vitest で検証する
- 絞り込み・採点・学習はブラウザ内。サーバーへの往復は属性表 1 回と、言葉を送るたび 1 回
- `vite dev` では adapter-cloudflare が `wrangler.toml` のバインディングを再現する。AI はリモート実行で **課金対象**、KV はローカル

## 7. 未決事項・今後

- **精度の評価セットの育て方**: `src/eval/cases.ts` に代表的な言葉 32 個と「上位に来てほしいサーバー」（説明文に根拠がある host）か「上位 5 件が満たすべき条件」（メアド不要など）を置き、`pnpm eval` で recall@5 / recall@10 / MRR / 条件達成率 / 平均応答時間を出す（Clef 実機、`fresh` でキャッシュを読まずに判定し直す）。曖昧なケース（初心者雑談・小さめ）は期待の根拠が弱いので、結果を見ながら入れ替える。
  2026-10-17 の推移（21 件 → 32 件で基準が変わる）: 86% → 読み取りの規模・流速をソフトに 88% → 規模を読者数に・初心者向けの活気 89%（21 件）/ 82%（32 件）→ 抜粋を足して 74% → 抜粋を外す 83%（再ランキングを足しても 84% で誤差、応答 +1.2 秒なので外す）→ 招待制を既定に含めて 81%（期待 host は受付中だけなので招待制が上位に入るぶん下がる）→ バッチ 16 件で 86%。残る弱点: 長文歓迎（みすきーすくえあ 6 位）、LTL の無い鯖の「静か」（ちらのーと・鳥籠すきー 30 位台）、二次創作（Mivatter 26 位）
- **判定する候補の絞り込み**: 今は scope の全サーバーを噛み合い判定にかける。ブラウザ側のハードフィルターを通る候補だけ送れば、招待制・停止中を含めるとき（約 580 件 → 73 本）の時間とコストを大きく減らせる。設定を広げたときに欠けた分だけ読み足す仕組みが要る
- **埋め込みで候補を絞ってから Clef に渡す案は使えない**（2026-10-24、32 言葉、招待制まで 182 件。基準 = 全サーバー 13 バッチ recall@5 74% / @10 87%）: bge-m3 の上位 16 件で 60% / 64%、48 件でも 66% / 72%、plamo-embedding-1b は 69% / 77% だが応答 4.7 秒。「英語で話せる」「静かな場所」のように説明文の意味で決まる言葉を埋め込みが拾えず、字面の一致（文字バイグラム + IDF）を足しても基準で上位 5 だった 48 件のうち 16 件が候補に入らなかった。Clef の 1 言葉 1,135 Neurons は、対象を減らすのではなく state のトークンを減らす方向でしか下げられない。実験の切り替え（`/api/intent` の `candidates` と `embed`）と `src/lib/server/embed.ts` は評価用に残す。
  なお評価セットの期待 host のうち `kasei.ski`・`misskey.design`・`waff-skey.net` が一覧から消えた（2026-10-24）ので、以前の 86% とは比べられない
- **`clef-flash` は使えない**: A/B（32 言葉、招待制まで 185 件）で recall@5 81 → 48%、MRR 88 → 53% と大きく落ち、しかも平均応答が 2.2 → 3.3 秒と遅かった（2026-10-17）
- **スキーマ更新時の再計算**: `VIBE_VERSION` を上げると欠けが `waitUntil` で 40 件ずつ埋まる。本番では warm を先に回してから deploy する
- **学習率と重みの校正**: `LEARN_LIKE` 0.3 / `LEARN_PASS` 0.15 / 8 スワイプで最大重み 3、相対値と確信度の係数は初期値
- **連合の情報**: 「友達のいる鯖と繋がれるか」は実際のニーズなので、misspace 側でキャッシュ API ができたら条件に加える
- **結果の多様性**: 大手が上位を独占する場合、規模をばらけさせる再ランキングを検討
- ~~**cron の内製化**~~: 2026-10-19 に Cron Triggers へ移した（例文の温めのみ。雰囲気の欠けはアクセスのたびに応答後に埋まる）
- **サーバー運営者向けの異議申立て**: 雰囲気判定に納得できない運営者が再判定を依頼できる導線
- **人を見つける（マッチング）**: 参加した人の Misskey プロフィールと代表ノートをマッチングアプリの見た目でスワイプし、右スワイプは「気になる」（非公開）、明示の「フォローする」ボタンが Misskey でのフォロー、相互フォローになったらマッチ。並びは共通のフォロー先と、本人の公開ノートから Clef が推定した話題。missmatch が預かるのは参加の記録・推定した数値・本人のフォロー一覧だけ。非参加者のデータは使わず、相手サーバーに未認証で行かない。30 人までデッキを開かない。設計は [PEOPLE.md](PEOPLE.md)（v6.4、2026-10-28）、敵対的評価 3 ラウンドの記録は [PEOPLE-redteam.md](PEOPLE-redteam.md)
