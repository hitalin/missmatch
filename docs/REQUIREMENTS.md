# missmatch 要件定義

最終更新: 2026-10-15（joinmisskey の実データ 653 件を分析して策定）

## 1. コンセプト

**「Misskey サーバー選びを、マッチングアプリの体験に変える」**

日本語の Misskey サーバーは 600 以上あり、そのうち新規登録を受け付けているのは約 100 件。
どこに入るかで体験は大きく変わるのに、比較材料は「サーバー名と一行説明」しかなく、
初心者は結局いちばん大きいサーバーに流れる。

missmatch は、ユーザーの希望（プロフィール）と各サーバーの **雰囲気**（説明文・ルール・実際の投稿から
AI が読み取ったもの）を突き合わせ、相性の良い順にカードで提示する。
ユーザーはスワイプで直感的に選び、気に入ったサーバーを一覧に残して見に行く。

### 姉妹プロジェクトとの関係

| プロジェクト | 立場 | 役割 |
|---|---|---|
| misspace | 見せる | 連合グラフを可視化し、ユーザー自身が判断する |
| **missmatch** | 勧める | 希望を聞いてこちらから候補を出す |

missmatch の結果からは misspace の連合グラフ（`?from=<host>`）へ遷移でき、
「勧められたサーバーがどの界隈と繋がっているか」を続けて確認できる。

### 設計原則

1. **最終判断はユーザー**: スコアは「見に行く順番」の提案であって、サーバーの優劣ではない。登録はさせない。
2. **理由を見せる**: なぜ上位なのかを軸ごとの一致理由として必ず表示する。判定できなかった軸は「未判定」と正直に出す。
3. **実データで校正する**: 質問の選択肢や閾値は、joinmisskey の実分布に合わせる。勘で決めない。
4. **サーバーに礼儀正しく**: 各サーバーへの API 呼び出しは 1 週間に 1 回程度（KV キャッシュ）。User-Agent を名乗り、タイムアウトを守り、LTL を公開していないサーバーには触らない。
5. **ユーザー情報を持たない**: 回答は推薦の計算にだけ使い、保存しない。ログインもクッキーもなし。

## 2. 対象ユーザー

- **P1: Misskey を始めたい人**。Fediverse 用語に不慣れ。misskey.io 以外の選択肢を知らない。
- **P2: サブアカウントの居場所を探している経験者**。「創作垢を置ける落ち着いたサーバー」など目的が具体的。
- 共通: 日本語話者、スマートフォンで片手操作、所要時間 3 分以内。

## 3. スコープ

### 対象サーバー

- joinmisskey (`instanceapp.misskey.page/instances.json`) に登録され、`isAlive` かつ `langs` に `ja` を含む
- **新規登録を受け付けている**（`nodeinfo.openRegistrations`、無ければ `meta.disableRegistration` から判定）
- 2026-10 時点の実数: 日本語 653 件 → 登録可能 **97 件**

### やらないこと

- アカウント作成・ログイン・サーバーへの投稿
- サーバーの「品質」や「安全性」のランキング（モデレーション判定は misscore の領域）
- 多言語対応（日本語サーバーの雰囲気判定に特化する）
- ユーザーごとの履歴保存やレコメンドの学習

## 4. 機能要件

### F1. プロフィール作成（診断）

7 問、各 1 タップ。「こだわらない」を選んだ軸は採点から外す。

| id | 質問 | 選択肢 | 使い方 |
|---|---|---|---|
| genre | 中心に投稿したい話題 | 雑談 / 創作 / 技術 / ゲーム / アニメ・推し活 / 特に決めていない | 雰囲気軸 `genre.*` と照合 |
| pace | TL の流速 | のんびり / ほどほど / にぎやか / こだわらない | `npd15`（15 日平均投稿数/日）を 3 段階化 |
| scale | 規模 | 小さな / 中規模 / 大手 / こだわらない | `usersCount` を 3 段階化 |
| tone | 空気感 | ほのぼの / ドライ・自由 / どちらでも | 雰囲気軸 `tone` `strictness` |
| age | 年齢 | 18 歳以上 / 18 歳未満 | **ハードフィルター**: 未成年に 18+ サーバーを出さない |
| nsfw | 成人向け | 見たくない / 気にしない / 歓迎 | 雰囲気軸 `nsfw` |
| community | 関わり方 | 気軽に入りたい / 濃い関係を築きたい | 雰囲気軸 `newcomerFriendly` `closedCommunity` |

**旧版からの変更**: 「新規登録について（すぐ使いたい / 承認待ちでも可）」を削除。
実データでは登録可能 97 件のうち承認制は 1 件のみで、質問として意味がなかった。
承認制はカード上のタグとして表示する。

**閾値の根拠**（登録可能 97 件の分布）:

| 軸 | 区分 | 閾値 | 件数 |
|---|---|---|---|
| pace | のんびり | < 100 投稿/日 | 45 |
| pace | ほどほど | 100〜5,000 | 41 |
| pace | にぎやか | ≥ 5,000 | 11 |
| scale | 小さな | < 100 人 | 23 |
| scale | 中規模 | 100〜1,000 | 42 |
| scale | 大手 | ≥ 1,000 | 32 |

中央値は 127 投稿/日・456 人。どの選択肢を選んでも候補が 10 件以上残る。

### F2. 年齢制限の判定

説明文とサーバールールから **登録年齢の制限** を判定する。
内容の成人向け度（nsfw）とは別の概念であり、混同しない。

- `18+`: 「18歳以上限定」「満18歳以上の方のみ」「18歳以上であること」「18歳未満は登録/利用できません」など、**登録者の年齢を制限する文言**
- `13+`: 「13歳未満の登録は禁止」など
- 該当しなければ `unknown`

旧版の正規表現（`成人|nsfw|r-?18` など）は、「未成年の自撮りは禁止」「NSFW には CW を付けて」「R-18 は投稿禁止」のような
**内容ルール**まで 18+ と誤判定し、登録可能 97 件中 16 件がヒットしたうち 11 件が誤検出だった
（未成年者が運営するサーバーまで 18+ 扱いになっていた）。一方で「18歳未満の登録は禁止」という最も多い言い回しを拾えず、
真に 18+ のサーバー 8 件を未成年に提示してしまう状態だった。

新しい判定を同じ 97 件に適用した結果: 18+ が 13 件、13+ が 3 件、誤検出 0 件（2026-10-15 に目視確認）。
コンテンツの成人向け度は Clef の `nsfw` 軸に任せる。

### F3. 雰囲気プロファイル（VibeProfile）

各サーバーについて以下を Cloudflare Workers AI の決定モデル **Clef**（`@cf/cloudflare/clef`）に 1 リクエストで問う。
Clef は文章を生成せず、型付きの質問に校正済みの確率で答える。

| 軸 | 型 | 内容 |
|---|---|---|
| genre.general / creative / tech / game / otaku / niche | noul（各 0..1） | その話題が **目立つか**。独立に問うので「創作もアニメも多い」サーバーを表現できる |
| tone | score 4 段階 → 0..1 | 殺伐 → ドライ → 穏やか → ほのぼの |
| strictness | score 3 段階 → 0..1 | ルールの厳しさ |
| newcomerFriendly | noul | 初心者が会話に入りやすいか |
| nsfw | noul | 成人向け投稿が目立つか |
| closedCommunity | noul | 身内ノリが強いか |

**旧版からの変更**: genre は 7 択の `choice`（確率の合計が 1）だったため、
創作 50% / 推し活 50% のサーバーはどちらの希望者にも 0.5 しか出せなかった。
軸ごとの独立した noul に変え、`adult` ジャンルは `nsfw` 軸と重複するため廃止した。

**state に渡す情報**: サーバー名、説明文、ルール、ユーザー数、投稿数/日、最近の投稿サンプル。
Clef のコンテキストは 65K トークンで、サンプル 50 件でも 3K トークン程度に収まる。

### F4. 投稿サンプリング

- 未認証で `POST /api/notes/local-timeline` を叩き、renote と添付のみの投稿を除く
- `meta.policies.ltlAvailable` が false のサーバーには **リクエストしない**（登録可能 97 件中 7 件）。説明文とルールだけで判定する
- 100 件取得して **50 件** を使う。URL・メンションを除き、1 件 200 文字まで
- **1 ユーザーあたり最大 5 件**。瞬間的な LTL は 1 人の連投で埋まりがちで、そのままでは個人の雰囲気を測ってしまう
- CW 付き投稿は CW 本文を先頭に付けて含める（成人向け度の手がかりになる）
- タイムアウト 8 秒、失敗は空配列（判定は続行）

### F5. 候補選定と採点

1. ハードフィルター: 日本語・登録受付中・（未成年なら）18+ を除外
2. 雰囲気判定済みのサーバーは全件、未判定は活発な順（`dru15`）に最大 40 件を候補にする
3. 軸ごとの一致度（0..1）× 重みの加重平均 × 100 を相性スコアとする

| 軸 | 重み | 一致度 |
|---|---|---|
| genre | 3 | `vibe.genre[希望]` |
| pace | 2 | 一致 1 / 隣接 0.4 / それ以外 0 |
| scale | 1.5 | 同上 |
| tone | 2 | warm: `tone`、dry: `(1 - tone + 1 - strictness) / 2` |
| nsfw=avoid | 4 | `1 - nsfw` |
| nsfw=welcome | 2 | `nsfw` |
| community=easyEntry | 2 | `(newcomerFriendly + 1 - closedCommunity) / 2` |
| community=deep | 1 | `0.5 + closedCommunity / 2` |

- 雰囲気未判定のサーバーは雰囲気系の軸を 0.5 とする（判定済みの「問題なし」より下に沈む）
- 同点は `dru15` の多い順
- 上位 10 件をスワイプデッキに積む

### F6. 提示とマッチ

- カード: バナー、アイコン、名前、相性 %、雰囲気タグ、一致理由（✓）、説明文、人数・投稿数/日、承認制・メアド不要などの補足
- 右スワイプ / ♥ でいいね、左 / ✕ でパス、`i` または ↑ で詳細展開。キーボード操作対応
- 相性 70% 以上に ♥ すると「マッチしました！」演出
- いいね一覧から本体と misspace の連合グラフへ遷移できる

### F7. 事前計算（warm）

- `POST /api/warm?limit=&offset=` を Bearer トークン付きで外部 cron から叩く
- **対象は推薦され得るサーバーだけ**（日本語・登録受付中）。旧版は閉鎖中を含む 653 件を計算対象にしており、コストが約 7 倍無駄だった
- 活発な順に処理する。全件でも 97 件なので、1 回の呼び出しで完了できる

## 5. 非機能要件

| 項目 | 要件 |
|---|---|
| レイテンシ | 全件キャッシュ済み: 1 秒以内。コールド: 未判定 40 件 × 並列 8 で 20 秒以内を目標 |
| コスト | Clef 入力 $0.24/M トークン。1 サーバー約 3K トークン → 97 件のフル更新で約 $0.07。週 1 更新なら月 $0.3 程度 |
| キャッシュ | VibeProfile: KV 7 日。サーバー一覧: KV 1 時間。スキーマ変更時は `VIBE_VERSION` を上げて無効化 |
| 外部負荷 | 各サーバーへの LTL 取得は 7 日に 1 回。並列 8。`User-Agent: missmatch/1.0` |
| Workers 制限 | 1 リクエストのサブリクエスト上限（無料 50 / 有料 1,000）に注意。候補 40 件 × (LTL + AI + KV) は有料プラン前提 |
| プライバシー | 回答・いいねはブラウザ内のみ。サーバー側に保存しない。アクセス解析なし |
| アクセシビリティ | キーボードのみで診断からスワイプまで完了できる。ダークモード対応 |
| 対応環境 | スマートフォン幅（〜480px）を基準。PC では中央寄せ |

## 6. アーキテクチャ

```
joinmisskey instances.json ──→ normalizeInstance ──→ ServerInfo[]（KV 1h）
                                                       │
診断回答 ──→ Preference ──→ hardFilter ──→ selectCandidates（判定済み全件 + 未判定 40 件）
                                                       │
                              ┌── KV hit ──→ VibeProfile ──┐
                              │                            │
                              └── miss ──→ LTL 50 件 ──→ Clef ──→ VibeProfile（KV 7d）
                                                       │
                                     scoreServer × rankServers ──→ 上位 10 件
```

- SvelteKit + adapter-cloudflare。ロジックは `src/lib/*.ts` の純粋関数に寄せ、vitest で検証する
- `vite dev` ではバインディングが無いため、KV はプロセス内メモリ、Clef は無効（雰囲気未判定として動く）

## 7. 未決事項・今後

- **重みの校正**: 実際に 97 件の VibeProfile を集め、スコア分布（70% 到達率、上位 10 件の多様性）を見て重みと「マッチ」閾値を調整する
- **結果の多様性**: 大手が上位を独占する場合、規模をばらけさせる再ランキングを検討
- **cron の内製化**: Cloudflare Cron Triggers で warm を回せれば外部 cron が不要になる（adapter-cloudflare の scheduled handler 対応を確認）
- **サーバー運営者向けの異議申立て**: 雰囲気判定に納得できない運営者が再判定を依頼できる導線
