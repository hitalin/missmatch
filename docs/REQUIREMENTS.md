# missmatch 要件定義

最終更新: 2026-10-15（joinmisskey の実データ 653 件を分析して策定。同日、固定 7 問の診断 → 適応型の診断 → プロフィール編集 → **スワイプから学ぶ**へと改訂）

## 1. コンセプト

**「Misskey サーバー選びを、マッチングアプリの体験に変える」**

日本語の Misskey サーバーは 600 以上あり、そのうち新規登録を受け付けているのは約 100 件。
どこに入るかで体験は大きく変わるのに、比較材料は「サーバー名と一行説明」しかなく、
初心者は結局いちばん大きいサーバーに流れる。

missmatch は、ユーザーの希望と各サーバーの **実用面の属性**（ドライブ容量、登録要件、広告、更新状況など）と
**雰囲気**（説明文・ルール・実際の投稿から AI が読み取ったもの）を突き合わせ、相性の良い順にカードで提示する。
ユーザーはスワイプで直感的に選び、気に入ったサーバーを一覧に残して見に行く。

マッチングアプリの定石をそのまま写す。**好みは質問で聞かず、スワイプから学ぶ**。
オンボーディングは 3 画面 30 秒（年齢・R-18・ひとこと）で、すぐデッキに入る。♥ と ✕ のたびにサーバーの
特徴ベクトルから好みを更新し、次の 10 枚を並べ替える。明示的な条件は「発見の設定」1 画面に、
絶対条件（Hinge の Dealbreaker）のトグルと、1 タップで決まるチップ・セグメントだけを置く。
プロフィール（設定・学習した好み・いいね・パス）はブラウザに保持され、作り直させない。

質問文を実行時に生成することはしない。生成しても、その質問に対する 97 サーバー分の答えが無ければ候補を絞れないからである。
代わりに Clef には 2 つの判定を任せる。(1) 各サーバーの雰囲気（事前計算）、(2) ユーザーの「ひとこと」と各サーバーの
説明文・ルールが噛み合うか（診断ごと、97 件を直接判定）。後者により、質問バンクに無い切り口（例: 病み垢の居場所）でも
サーバーの説明文に書いてあれば拾える。属性表は事前計算し、絞り込みと採点はブラウザ内で完結させる。

### 姉妹プロジェクトとの関係

| プロジェクト | 立場 | 役割 |
|---|---|---|
| misspace | 見せる | 連合グラフを可視化し、ユーザー自身が判断する |
| **missmatch** | 勧める | 希望を聞いてこちらから候補を出す |

missmatch の結果からは misspace の連合グラフ（`?from=<host>`）へ遷移でき、
「勧められたサーバーがどの界隈と繋がっているか」を続けて確認できる。

### 設計原則

0. **実際に差がある項目だけ聞く**: サーバー間で差がつかない質問（例: 投稿の最大文字数は 97 件中ほぼ全てが 3,000 字）は聞かない。
1. **最終判断はユーザー**: スコアは「見に行く順番」の提案であって、サーバーの優劣ではない。登録はさせない。
2. **理由を見せる**: なぜ上位なのかを軸ごとの一致理由として必ず表示する。判定できなかった軸は「未判定」と正直に出す。
3. **実データで校正する**: 質問の選択肢や閾値は、joinmisskey の実分布に合わせる。勘で決めない。
4. **サーバーに礼儀正しく**: 各サーバーへの API 呼び出しは 1 週間に 1 回程度（KV キャッシュ）。User-Agent を名乗り、タイムアウトを守り、LTL を公開していないサーバーには触らない。
5. **ユーザー情報を持たない**: 回答は推薦の計算にだけ使い、保存しない。ログインもクッキーもなし。

## 2. 対象ユーザー

- **P1: Misskey を始めたい人**。Fediverse 用語に不慣れ。misskey.io 以外の選択肢を知らない。
- **P2: サブアカウントの居場所を探している経験者**。「創作垢を置ける落ち着いたサーバー」など目的が具体的。
- 共通: 日本語話者、スマートフォンで片手操作、所要時間 3 分以内。

## 3. スコープ

### 対象サーバー

- joinmisskey (`instanceapp.misskey.page/instances.json`) に登録され、`isAlive` かつ `langs` に `ja` を含む
- 既定では **新規登録を受け付けている**サーバー（`nodeinfo.openRegistrations`、無ければ `meta.disableRegistration` から判定）
- 「登録のしかた」で招待制・停止中を含めると、登録停止中でも **生きている**（`dru15` ≥ 1、1 日 1 人以上が読んでいる）サーバーも候補になる
- 2026-10 時点の実数: 日本語 653 件 → 登録可能 **97 件**、停止中で生きているもの **480 件**（うち 10 人未満の個人サーバー 278 件）、休眠 76 件

#### 登録状態の判定

公開情報に「招待制」の直接のフラグは無い。次の順で判定する。

| 状態 | 判定 | 97 + 480 件での数 |
|---|---|---|
| open | 登録受付中で承認不要 | 96 |
| approval | 登録受付中で `approvalRequiredForSignup` | 1 |
| invite | 停止中で、`policies.canInvite`（一般ユーザーが招待コードを発行できる）か、説明文・ルールに「招待」「invite」 | 約 90 |
| closed | 停止中でそれ以外（misskey.io のような一時停止を含む） | 残り |

### やらないこと

- アカウント作成・ログイン・サーバーへの投稿
- サーバーの「品質」や「安全性」のランキング（モデレーション判定は misscore の領域）
- 多言語対応（日本語サーバーの雰囲気判定に特化する）
- ユーザーごとの履歴保存やレコメンドの学習

## 4. 機能要件

### F1. オンボーディングと発見の設定

#### F1-a. オンボーディング（2 画面）

1. 年齢: 18 歳以上 / 18 歳未満（2 択、必須。18 歳未満には 18+ のサーバーを出さない）
2. R-18 の投稿: 見たくない / 気にしない / 歓迎（3 択、必須）

終わると即デッキ。追加の質問はしない。

#### F1-b. 検索ボックス「どんな場所を探している？」

デッキの上に常駐する自由記述の検索ボックス（emoji-samurai の suggest のように、設定とは分離した検索 UI）。
検索すると Clef が 2 種類の判定をし、デッキが並び替わる。反映中は「「〜」に合う順に並べています」と表示し、✕ で外せる。

1. **発見の設定の自動入力**: 話題（noul × 6）、空気感・関わり方・ルール（choice: 左 / 右 / 言及なし）、規模・流速（choice）、
   メアド不要・広告なし・GTL・本家（noul）を読み取り、確率 0.6（noul は 0.7）以上のものだけで**既定値のままの項目**を埋める。
   ユーザーが触った項目は上書きしない。年齢と R-18 は読み取らない
2. **噛み合い確率（affinity）**: 候補 97 件それぞれについて「説明文・ルール・雰囲気タグはユーザーの望む使い方と噛み合うか」を
   `noul` で問う（12 件 × 9 バッチ並列、1.6〜2.3 秒）。採点の軸（重み 3）になる

実測（2026-10-15、Clef 実機）: 「病み垢として運用したい。弱音や愚痴を吐いても浮かない、静かな場所がいい」→ 噛み合い 1 位 yami.ski 0.92。

#### F1-c. 発見の設定（「あなた」タブ、1 画面）

| 区分 | 項目 | 操作 | 効き方 |
|---|---|---|---|
| 基本 | 年齢 / 登録のしかた / R-18 | 2 択 / チップ（受付中・承認制・招待制・停止中、既定は前 2 つ）/ 3 択 | 年齢と登録のしかたはハードフィルター。R-18 は「見たくない」で重み 4、「歓迎」で重み 2 |
| 話したいこと | 上記 14 区分（特定テーマを除く） | チップ、複数可 | 選んだ話題のうち最大の `vibe.genre` を重み 3 で加点 |
| 空気感 | 空気（ドライ ↔ ほのぼの）/ 関わり方（濃い身内 ↔ 初心者歓迎）/ ルール（ゆるめ ↔ しっかり） | 3 段セグメント | 雰囲気軸を重み 2 / 2 / 1.5 で加点 |
| 規模と流速 | 個人（〜9 人）/ 小 / 中 / 大、のんびり / ほどほど / にぎやか | チップ、複数可、空 = 指定なし | **ハードフィルター**（選んだ区分だけ出す）。10 人未満を個人とするのは、説明文に「個人サーバー」とある鯖がほぼ 5 人以下だったため |
| 絶対条件 | メアド不要 / 広告なし / GTL あり / 本家のみ / 最新版（1 ヶ月以内） | トグル | **ハードフィルター**。該当件数を常時表示し、5 件未満で警告 |
| 履歴 | パスした鯖をもう一度見る | ボタン | パス履歴を消す |

97 件での分布（2026-10）: 18+ 13 件、メアド不要 11 件、広告あり 14 件、GTL 無効 17 件、本家 51 件、最新 50 件、
規模 23 / 42 / 32、流速 45 / 41 / 11。

### F1.5 スワイプからの学習

- サーバーごとに特徴ベクトル（0..1）を持つ: 話題 6 軸、空気、ルール、初心者歓迎度、R-18、規模、流速、ドライブ容量、本家、GTL、メアド不要、広告なし、更新の新しさ。判定できない特徴は含めない
- 好み `taste` は特徴ごとに -1..1。♥ で `+0.3 × (f − 0.5) × 2`、✕ で `−0.15 × …`（パスは弱い信号）。-1..1 にクランプ
- 採点の軸として `tasteFit = 0.5 + Σ t·(f−0.5) / Σ|t|·0.5 / 2` を、重み `min(3, スワイプ数 / 8 × 3)` で加える。最初は効かず、8 スワイプで最大
- デッキは 10 枚ずつ。束を見終わると、学習した好みで次の 10 枚を並べ直す（見ている最中に順番は変えない）
- ↶ 戻す は直前の学習を同じ量だけ戻す
- 「あなた」タブに学習した傾向をチップで出す（|t| ≥ 0.3 の上位 5 つ、例: 「小規模」「弱音を吐ける」）。個別に忘れられ、全部リセットもできる
- パスしたサーバーは二度と出さない（Tinder と同じ）。「よくないね」タブから個別に戻せる

### F2. 年齢制限の判定

説明文とサーバールールから **登録年齢の制限** を判定する。
内容の成人向け度（nsfw）とは別の概念であり、混同しない。

- `18+`: 「18歳以上限定」「満18歳以上の方のみ」「18歳以上であること」「18歳未満は登録/利用できません」など、**登録者の年齢を制限する文言**
- `13+`: 「13歳未満の登録は禁止」など
- 該当しなければ `unknown`

旧版の正規表現（`成人|nsfw|r-?18` など）は、「未成年の自撮りは禁止」「NSFW には CW を付けて」「R-18 は投稿禁止」のような
**内容ルール**まで 18+ と誤判定し、登録可能 97 件中 16 件がヒットしたうち 11 件が誤検出だった
（未成年者が運営するサーバーまで 18+ 扱いになっていた）。一方で「18歳未満の登録は禁止」という最も多い言い回しを拾えず、
真に 18+ のサーバー 8 件を未成年に提示してしまう状態だった。

新しい判定を同じ 97 件に適用した結果: 18+ が 13 件、13+ が 3 件、誤検出 0 件（2026-10-15 に目視確認）。
コンテンツの成人向け度は Clef の `nsfw` 軸に任せる。

### F3. 雰囲気プロファイル（VibeProfile）

各サーバーについて以下を Cloudflare Workers AI の決定モデル **Clef**（`@cf/cloudflare/clef`）に 1 リクエストで問う。
Clef は文章を生成せず、型付きの質問に校正済みの確率で答える。

| 軸 | 型 | 内容 |
|---|---|---|
| genre.*（15 区分、下表） | noul（各 0..1） | その話題が **目立つか**。独立に問うので「創作もアニメも多い」サーバーを表現できる |
| tone | score 4 段階 → 0..1 | 殺伐 → ドライ → 穏やか → ほのぼの |
| strictness | score 3 段階 → 0..1 | ルールの厳しさ |
| newcomerFriendly | noul | 初心者が会話に入りやすいか |
| nsfw | noul | 成人向け投稿が目立つか |
| closedCommunity | noul | 身内ノリが強いか |

**ジャンルの区分**は、登録可能な日本語サーバー 97 件の名前・説明文・ルールに実在するコンセプトを集計して決めた（2026-10-15）。
「創作」「アニメ・推し活」は粒度が粗く、イラスト鯖と小説鯖、作品ファン鯖と VR 鯖を区別できなかったため分割した。

| 区分 | 実在する例 |
|---|---|
| 雑談 | すしすきー、Misskey.gg、まっちゃすきー ほか多数 |
| 日記・ひとりごと | わふふすきー、metreee、たけすきー、だらだら倶楽部 |
| イラスト・漫画を描く | お絵かきすきー、misskey.art、misskey.design、Pika.moe |
| 小説・文章 | misskey.design、イノカシラシクィイ |
| 音楽・歌 | ぼすきー（合成音声）、nicomedkey、にしかわたかのりすきー |
| ものづくり・制作 | くらふたーず、roboticskey、DAZ（3DCG）、misskey.doujin.games |
| 技術・IT | みすてむず、競プロ鯖、労働者たちの Misskey |
| ゲーム（TRPG・ボドゲ含む） | 卓すきー、いかすきー、パズルゲームすきー |
| アニメ・漫画 | 星海天測団、Misskirara、misskey.stream |
| 推し活・ファン | LIVE THE@TER NET、ゆにくすきー、ESkey、封神台、u-stella |
| VRChat・メタバース | にりらみすきー部、ぶいちゃ、Resonite.love、バーチャルケモミミ |
| 食べ物・お酒 | ぽてとすきー、うま味、kusso-yotta |
| 動物・ペット | いぬすきー、kusso-yotta |
| 愚痴・弱音 | やみすきー、みつきー、かせいすきー |
| 特定テーマ（話題としては選べない） | 地域・職業などの限定サーバーの検出用 |

**旧版からの変更**: genre は 7 択の `choice`（確率の合計が 1）だったため、
創作 50% / 推し活 50% のサーバーはどちらの希望者にも 0.5 しか出せなかった。
軸ごとの独立した noul に変え、`adult` ジャンルは `nsfw` 軸と重複するため廃止した。

**state に渡す情報**: サーバー名、説明文、ルール、ユーザー数、投稿数/日、最近の投稿サンプル。
Clef のコンテキストは 65K トークンで、サンプル 50 件でも 3K トークン程度に収まる。

### F4. 投稿サンプリング

- 未認証で `POST /api/notes/local-timeline` を叩き、renote と添付のみの投稿を除く
- `meta.policies.ltlAvailable` が false のサーバーには **リクエストしない**（登録可能 97 件中 7 件）。説明文とルールだけで判定する
- 100 件取得して **50 件** を使う。URL・メンションを除き、1 件 200 文字まで
- **1 ユーザーあたり最大 5 件**。瞬間的な LTL は 1 人の連投で埋まりがちで、そのままでは個人の雰囲気を測ってしまう
- CW 付き投稿は CW 本文を先頭に付けて含める（成人向け度の手がかりになる）
- タイムアウト 8 秒、失敗は空配列（判定は続行）

### F5. 採点と提示順

1. ハードフィルター: 日本語・登録受付中・年齢・規模・流速・絶対条件
2. 軸ごとの適合度（0..1）× 重みの加重平均 × 100 を相性スコアとする。軸が無ければ 50
3. 適合度 0.6 以上の軸の理由をカードに出す（「創作の話題が多い」「書いてくれた希望と噛み合う」「いいねした鯖と似ている」）
4. 雰囲気未判定のサーバーは雰囲気系の軸を 0.5 とする
5. 同点は `dru15` の多い順。スワイプ済みを除いて上位 10 件をデッキにする

| 軸 | 重み |
|---|---|
| R-18 = 見たくない | 4 |
| 話題、ひとことの噛み合い、学習した好み（最大） | 3 |
| 空気、関わり方、R-18 = 歓迎 | 2 |
| ルール | 1.5 |

### F6. 画面構成と提示（Misskey と Tinder の間）

- **アプリシェル**: 幅 480px のモバイル前提。画面下に 4 タブ（さがす / ♥ いいね / ✕ よくないね / あなた）。900px 以上では左の縦レールになり、本文は最大 1080px。Tinder Web と Misskey デスクトップの折衷
- **配色・部品**: Misskey のアクセント #86b300、パネル（角丸 14px、細い境界線）、ピルボタン。ダークモード対応。`backdrop-filter` は使わない（モバイルで重い）
- **オンボーディング**: ヒーロー → 年齢 → R-18 → ひとこと の 3 画面。設定が保存済みなら出さない
- **あなた**: 学習した好み（チップ）、基本（年齢・登録のしかた・R-18）、話したいこと、空気感、規模と流速、絶対条件（トグル）。該当件数を上に常時表示
- **よくないね**: ✕ したサーバーの一覧（いいねと同じグリッド）。「戻す」でデッキに復帰する。Tinder は見せないが、間違えて飛ばした鯖を救う導線として置く
- **さがす（カード）**: Tinder のカード。全面にバナー画像（無ければテーマ色のグラデーション）、下部グラデーション上に名前・ホスト・人数・投稿数、一致理由（✓）とタグのチップ、説明文 2 行。右上に相性 %、左上に「あと N 件」と「⚙ 条件」。ドラッグで LIKE / NOPE のスタンプ。操作列は ↶ 戻す / ✕ / i / ♥。タップか i でボトムシートに詳細（デスクトップではカードの右に常時表示）。条件に合うカードが無いときと束を見終わったときは「条件を見直す」
- **マッチ演出**: 相性 70% 以上に ♥ で全面オーバーレイ
- **いいね**: 2 列のタイルグリッド（バナー + 名前 + 相性）。各タイルから本体 / misspace の連合 / 外す
- **画像**: アイコン・バナーは joinmisskey が軽量化して配っているもの（webp、アイコン約 3KB）を使い、各サーバー本体には取りに行かない。97 件に個別に画像を取りに行くのが「重さ」の一因だった
- **描画の軽さ**: 属性表（97 件）は `$state.raw` で深い reactivity を付けない。一言の入力中は採点・情報利得を再計算しない（採点に効く回答だけを文字列キーにして依存を切る）。保存は 250ms デバウンス。カードは `contain: content` と `translate3d`

### F7. 事前計算（warm）

- `POST /api/warm?limit=&offset=` を Bearer トークン付きで外部 cron から叩く
- **対象は推薦され得るサーバーだけ**（日本語・登録受付中）。旧版は閉鎖中を含む 653 件を計算対象にしており、コストが約 7 倍無駄だった
- 活発な順に処理する。全件でも 97 件なので、1 回の呼び出しで完了できる

## 5. 非機能要件

| 項目 | 要件 |
|---|---|
| レイテンシ | 属性表 API は Clef を待たない（キャッシュ済み分を即返し、欠けは `waitUntil` で応答後に計算）。ひとことの読み取り: 12 件 × 9 バッチ並列で 1.6〜2.3 秒（実測）。「おすすめを見る」はブラウザ内計算で即時 |
| コスト | Clef 入力 $0.24/M トークン。雰囲気: 1 サーバー約 3K トークン → 97 件のフル更新で約 $0.07、週 1 更新なら月 $0.3 程度。ひとことの読み取り: 1 回あたり約 30K トークン → 約 $0.01 |
| キャッシュ | VibeProfile: KV 7 日。サーバー一覧: KV 1 時間。スキーマ変更時は `VIBE_VERSION` を上げて無効化 |
| 外部負荷 | 各サーバーへの LTL 取得は 7 日に 1 回。並列 8。`User-Agent: missmatch/1.0` |
| Workers 制限 | 1 リクエストのサブリクエスト上限（無料 50 / 有料 1,000）に注意。候補 40 件 × (LTL + AI + KV) は有料プラン前提 |
| プライバシー | プロフィール・いいねは `localStorage` のみ。ひとことは読み取りのために Clef へ送るが保存しない。アクセス解析なし |
| アクセシビリティ | キーボードのみでオンボーディングからスワイプまで完了できる（← → で判定、↑/Space で詳細、Backspace で戻す）。ダークモード対応 |
| 対応環境 | スマートフォン幅（〜480px）を基準。PC では中央寄せ |

## 6. アーキテクチャ

```
joinmisskey instances.json ──→ normalizeInstance ──→ ServerInfo[]（KV 1h）
                                                       │ isJoinable
GET /api/servers ──→ KV の VibeProfile を全件読む ──→ ServerProfile[]（約 160KB）──→ ブラウザ
                     └─ 欠け（活発な順に 40 件）は waitUntil で応答後に LTL 50 件 → Clef → KV 7d

ひとこと ──→ POST /api/intent ──→ Clef ×(1 + ⌈97/12⌉) 並列 ──→ { 設定の読み取り, affinity } ──→ 発見の設定へ
                                                                                             │
     localStorage ⇄ SavedProfile{prefs, taste, swipes, liked, passed} ──→ buildDeck（ブラウザ内）──→ 10 枚 ──→ スワイプ ──→ learn
```

- `/api/servers` と `/api/intent` は `scope=open`（既定、約 100 件）と `scope=all`（招待制・停止中を含む約 580 件）を持つ。全件はその設定にしたときだけ取りに行く。全件の雰囲気は欠けを 40 件ずつ `waitUntil` で埋めるか、`/api/warm?scope=all` で事前計算する（約 480 件 × 3K トークン ≈ $0.35）
- Clef が判定を返せないサーバー（例: misskey.stream で `3043: The model did not produce a valid decision response`）は、投稿サンプル無しで再挑戦し、それでも駄目なら失敗マーカーを 1 日置く。毎リクエストの再試行と、欠けが残ることによる属性表キャッシュの不成立を防ぐ
- 組み立て済みの属性表は欠けが無いときだけ KV に 5 分キャッシュする（本番で 1.8 秒 → 1 秒未満）
- SvelteKit + adapter-cloudflare。設定（`prefs.ts`）、特徴ベクトル（`features.ts`）、学習と採点（`match.ts`）、
  ひとことの変換（`intent.ts`）、保存形式（`profile.ts`）は純粋関数で、vitest で検証する
- 絞り込み・採点・学習はブラウザ内。サーバーへの往復は属性表 1 回と、ひとことを反映するとき 1 回
- `vite dev` では adapter-cloudflare が `wrangler.toml` のバインディングを再現する。AI はリモート実行で**課金対象**、KV はローカル

## 7. 未決事項・今後

- **噛み合い判定の高速化**: 現状 1.6〜2.3 秒。`clef-flash`（9B）に切り替えれば速くなるはずだが、順位の質が保てるか未検証
- **スキーマ更新時の再計算**: `VIBE_VERSION` を上げると欠け 97 件が `waitUntil` で 40 件ずつ埋まる。本番では warm を先に回してから deploy する
- **学習率と重みの校正**: `LEARN_LIKE` 0.3 / `LEARN_PASS` 0.15 / 8 スワイプで最大重み 3 は初期値。実際のスワイプで「数枚で傾向が出て、暴れない」かを見て調整する
- **重みと利得閾値の校正**: 97 件の VibeProfile は揃った。実際の回答ログは取らない方針なので、代表的なペルソナ（P1/P2）の回答を手で流し、質問順・スコア分布（70% 到達率、上位 10 件の多様性）を見て重み・`MIN_GAIN_BITS`・「マッチ」閾値を調整する
- **連合の情報**: misspace の疎通チェック（`federation/show-instance`）は未認証で取れるかがサーバー依存でキャッシュも無いため今回は見送った。「友達のいる鯖と繋がれるか」は実際のニーズなので、misspace 側でキャッシュ API ができたら質問に加える
- **結果の多様性**: 大手が上位を独占する場合、規模をばらけさせる再ランキングを検討
- **cron の内製化**: Cloudflare Cron Triggers で warm を回せれば外部 cron が不要になる（adapter-cloudflare の scheduled handler 対応を確認）
- **サーバー運営者向けの異議申立て**: 雰囲気判定に納得できない運営者が再判定を依頼できる導線
